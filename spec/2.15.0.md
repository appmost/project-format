# Appmost Project Format 2.15.0

Appmost Project Format 2.15.0 extends [2.14.0](https://www.appmost.ai/format/spec/2.14.0.md). Packages continue to use `documentVersion: 2` and the existing document fields. This release describes Web renderer support for existing behavior. The [release manifest](https://www.appmost.ai/format/releases.json) and [registry](https://www.appmost.ai/format/registry/2.15.json) identify the release and its artifacts.

## RevenueCat refresh and purchase state on the web

`reloadIAPSubscriptions` reads RevenueCat customer information for the existing Web Billing integration and identified account described in [2.13.0](https://www.appmost.ai/format/spec/2.13.0.md). It refreshes the purchase state without presenting checkout. The next action can run after a successful refresh even when the configured entitlement is inactive. A failed refresh follows the existing action error policy, which stops the sequence by default.

The existing built-in `iApState.validSubscriptionIds` is read-only. On the web it contains the configured active entitlement's product identifier, or an empty list when no such entitlement is active. `validIOSSubscriptionIds` and `validAndroidSubscriptionSkus` remain empty on the web. A change of account or integration clears the prior account's purchase state, and results from the old account cannot restore it. Existing web paywall and restore actions update the same purchase state when they complete.

## Scroll to a page in a paginated list

`scrollPagination` uses the active page's existing pagination list. Set `configuration.scrollPagination.target` to the variable containing the desired value and `targetProp` to the property path on each list item. The web renderer compares the text values without regard to case and scrolls to the first match. Set `animated: true` to request an animated scroll. Existing `scrollPaginationModel` encodings remain readable.

Paginated rows resolve their existing prototype references in the current slide. An empty list can show the existing `paginationEmptyReloadText` control when the page provides manual reload actions.

## List choices and modifications

The Web renderer supports two list modes of `showActionSheet` under the existing `configuration.actionSheetActionModel` object.

- `stringFromList` displays the list at `sourceId` and writes the selected value to `targetId`. An optional `sourceParams` property path supplies the display value. A custom target keeps the selected item. The configured `appActionsAfterClick` run after a list selection is written. An authored extra option also runs them unless `onlyPerformPostActionsForListActions` is enabled.
- `modifyList` operates on the current repeated row's item. An explicit `sourceId` selects the list. Otherwise the renderer uses the row's prototype source. `enableMoving` allows moving the item one position, and `enableDeletion` allows deleting it. Authored extra options run their action followed by `appActionsAfterClick`. The built-in move and delete options update the list directly. Cancel leaves the list unchanged.

## Legacy inset buttons

The Web renderer reads the existing `insetButton` variant, including legacy `cellid: 20`. It renders the first existing `buttons` model and follows the ordinary button and row action precedence. No new row fields are required.
